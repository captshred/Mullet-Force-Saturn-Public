# Combat animation key-pose prototype — NOT finished full-quality animation

Source gameplay: `20b0fcf743ace0e16f74cb3dcdf22fd93dd8ead9`, the latest remote running-bat visual milestone at inspection. Branch: `character-combat-animation-upgrade`. The separate `integration/latest-gameplay-fm-boost` branch was not used. Existing native SEQ/TON playback with sampled PCM instruments and PCM SFX is unchanged; this is not a full-song PCM recording. Audio source and generated CD assets are hash locked.

The request expressly permits a limited prototype if complete high-quality frames cannot be produced reliably. This build exercises that provision. It does **not** meet the finished 4–6 punch / 5–7 bat pose target. Each fighter has two new punch keys (chamber, extension) and two bat keys (windup, contact), with original idle used for punch entry/recovery. A generated guide edited from the actual approved sprites supplies shoulder/arm/torso candidates, converted with nearest sampling, binary transparency and the existing palette. Exact original opaque head/face/hair pixels and original planted lower bodies are retained at their original root. Native PNGs and source guide are retained for manual editing. This is guide-derived candidate art, not hand-drawn finished animation.

## Timing and behavior

No game simulation, speed, collision, input, hitbox, damage, attack length, hit-stop or audio changes. Punch counters 1–2 use approved idle, 3–5 chamber, 6–10 extension, 11–15 chamber, 16–24 approved idle. Existing punch active window remains 6–10. Both fighters share timings; requested heavy/agile style differentiation remains uncompleted.

Bat counters 1–11 use windup, 12–27 contact/follow hold, 28–36 windup recovery. The existing active interval, including its changing vertical hitbox, remains untouched. These sparse keys are **not** a convincing continuous arc yet: the bat changes angle abruptly and recovery reverses to the ready pose. Initial-swing, midpoint, follow-through and recovery drawings are still needed. There are no interpolated or mirrored idle sprites claimed as distinct attack frames.

Running-bat counters 1–5 preserve the prior carried-run bridge. From counter6 the new upper keys use the four existing alternating native run lower bodies, advancing once per6 attack-counter ticks from the cached last dash phase. Hit-stop freezes the simulation counter and therefore the phase. No stationary planted legs replace the running attack. The upright prototype upper body needs a proper forward-leaning running-specific swing and a more natural waist join; the moving attack's momentum/KO rules remain unchanged. All aerial attacks remain on original fallbacks.

## Allocation

Before: 410,464 bytes, 48,024 free,169 textures. Prototype: +43,488 bytes,+54 unique shared strips. Total: **453,952 bytes,4,536 free,223 textures**, against458,488 available texture bytes. All256-color palette entries are reused from `assets/gallery/GB0.TGA`; no new palette or CRAM allocation (existing8 banks /4096 bytes). The palette bytes are identical in every new TGA. Index0 is transparent;254/255 are excluded. Widths are8 aligned, heights even to preserve pinned SGL raster registration; allocation is32-byte aligned. Per-pose strips are globally interned. Two player instances and galleries share the resident bank. The54 new TGA files reside in the `COMBAT` CD subdirectory: placing them in the root exceeded the pinned Jo filesystem256-entry limit and failed at street S102 in the first emulator test. The directory-aware loader returns to the parent after each boot-time read; ISO validation recursively checks exact payloads and enforces the entry limit on every directory. The entire increment is preflighted before disc reads; draw/update never allocate, upload or read CD. Existing combat/fallback textures are retained. All original leg pixels from row48 through the ground, including upper thighs and high driven knees, are retained in the moving swing. The small remaining margin means additional finished poses require further budgeting before expansion; this prototype does not implement a cache.

Canvas160×112, root(64,108), is the existing128×96/body root(64,92) plus16 vertical transparent pixels and32 rightward weapon margin. The body is still88 pixels tall. Exact opaque original head region x39..88/y0..23 is retained at y+16, plus original lower rows48..95 at y+16. No resizing of original body parts occurs. Sparse horizontal strips are a separate opt-in attack renderer; idle/walk/run retain their original three-piece renderer. Hardware horizontal flip mirrors the complete assembled pose about the same root.
