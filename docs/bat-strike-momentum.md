## Actual alignment fault

The guide contact illustration is horizontally offset within its sheet cell. The preceding converter used a shared cell origin, then restored the original head and lower-body pixels. The resulting contact torso/arms/weapon remained20 native pixels left of the hip root; this was a source-registration error, not an SGL crop-offset or mirroring bug. Cycling four differently positioned running hip/leg crops underneath it amplified the disconnect. New contact conversion changes only that pose's source registration by+20 native pixels before restoring the original face/head/hair region. The shoulder/arm/hand/weapon group moves together with no scaling, grip change, or bat rotation alteration. Tests prove exact20px pixel translation for rows40..63 in the review canvas and a continuous opaque waist join. Windup upper pixels remain identical; original opaque head/face/hair pixels remain identical. Canvas160×112/root(64,108) remains unchanged: existing88px heroes, with transparent weapon margin.

The original idle lower crop also included detached cuff/glove components. Connected-component extraction keeps the native trouser/boot component and removes only18 Buck cuff pixels /120 Chuck glove pixels. No actual leg, boot or foot pixels move or change color. This clean lower is fixed for all36 bat attack counters, for both fighters/facings, including running attacks. Normal planted bat uses the same corrected visual keys; its input, movement, damage and timings are unchanged. Punch keys and complete punch assemblies are pixel-identical to the baseline. Idle, walk, dash and enemy sources remain intact.

`MF_BAT_MOMENTUM=1` selects the new packaging, rendering and limited movement. Default0 preserves prior behavior and bank; it requires the approved combat/running-bat visual configuration for builds.

At running-bat activation, the existing dash input/state exits immediately. The renderer immediately selects the planted bat windup, with no five-counter carry bridge and no advancing run-frame index during any swing phase. Contact counters12..27 and recovery28..36 retain their existing two-key prototype presentation; animation quality remains the preceding prototype, not a newly completed swing arc. Root and feet stay fixed relative to each other while world position slides.

Configurable integer constants in `src/bat_momentum_config.h`: `MF_BAT_SLIDE_NUM=3`, `MF_BAT_SLIDE_DEN=5`, `MF_BAT_SLIDE_TICKS=8`. Hurt/jump cancellation, stage clamps x26..614, shared two-player camera tether and recovery rules are unchanged. The baseline has no physical wall map/body collision; no new wall penetration or bypass is introduced, and no unimplemented wall system is claimed.
