# Level 2 direct-MIDI polyphony repair

Parent: `a5e524dbd774cdb502f38f36c9ab12149c9498c1` (`fix/level2-split-flame-audio`). Delivery branch: `fix/level2-polyphonic-sfx`. This is a source-only repair awaiting audible WebRetro confirmation.

1. **Confirmed cause:** the previous scheduler explicitly called `SND_StopSeq` on the oldest Shot when its two controls were busy. That intentionally truncated audible Shot PCM. Shot/Explosion also performed per-event volume/start sequence operations instead of independent sampler Note Ons. Those operations and replacement logic are removed.
2. **Sequence causality:** the pinned native StartSeq handler at `0x257e` calls `0x54d4`, which keys off the selected control and resets that control's channels. StopSeq (`0x263a`) also calls `0x54d4`. That routine matches slot owner against `control<<9`; it is not a global stop. Correctly addressed Shot/Explosion sequences should not stop Flame controls0/1. No captured WebRetro driver trace proves that sequence playback alone caused the reported cross-class interruption. Removing it addresses the requested architecture without inventing that proof.
3. **Physical stealing:** no hardware/WebRetro slot trace was available. Native instruction-level snapshot tests found zero active replacements with two persistent Flames and 2,000 subsequent leased one-shots. The driver can replace voices under saturation; this is explicitly tested. The repair does not patch private allocator flags, invent priority offsets, or claim stealing is impossible in a stalled/corrupt/unexpected driver state.
4. **Observed versus expected slots:** the C host SCSP mock observes a peak of10 live records during simultaneous two-player Attack/Loop handoffs plus two Shots and four Explosions. The actual 68K allocator execution tests observe a peak8 in controlled snapshots containing two persistent Flames and six one-shots. Neither result is a measured real Saturn count. Expected principal mix:8 in sustain, briefly10 during both handoffs, below32 hardware slots.
5. **Shot path:** controls2/3 each accept one `SND_CtrlDirMidi(control,0,1,control,60,110)` per accepted event. No early Note Off or stop. A control becomes reusable after34 actual VBlanks, exceeding22403/44100 seconds (~30.48 ticks at60Hz). Up to two new overflow events wait; additional NEW overflow drops with a counter. Existing PCM remains untouched.
6. **Explosion path:** controls4..7 use the same direct Note On, program0. Reuse after49 VBlanks exceeds15840/22050 seconds (~43.10 ticks). Four independent explosions may sound simultaneously; four additional NEW events can wait one batch (~0.82s at60Hz). Further new overflow drops. Rejected SDK submissions retain pending events and retry without marking the control active.
7. **Runtime sequence audit:** `src/wingsuit_audio.c` contains no `SND_StartSeq` or `SND_StopSeq`, and no sequence-status dependency. MAP/SEQ/TON loading and file contents are preserved. `SND_SetSeqVl` remains solely as the pinned driver's shared control-gain setup command, once per control during readiness (and the unchanged Flame preparation), never as per-event Shot/Explosion machinery. The native handler at `0x271a` stores each control's gain; `0x280e` applies it by owner and channel, including direct MIDI voices.
8. **Assignments:** all bank0, MIDI channel equals control, velocity110, submitted priority0.

   The pinned dispatcher at `0x2ece` forms context `(control<<9)+(channel<<5)` and saves both identifiers. Slot setup at `0x38c8` stores owner `control<<9` and key `(channel<<8)|note`, plus its own layer pointer. Program changes select the next note's layer; they do not retune an existing slot. Thus the eight pairs have disjoint bank/program/channel state; note60 can safely be reused across those pairs. No pitch/base-note change is needed. Shot base60, Explosion base72, and Flame bases60/61 remain byte-identical.
9. **Priority/allocation audit:** no priority, gain, tone, envelope, pitch, or mixer-table change. Native direct dispatch masks the command/priority byte with7; the normal allocator does not use a new per-event priority. All four actual tones use poly play mode0, one layer, no modulation slots. At `0x378a`, a zero-flags slot wins immediately, before same-note or same-control candidates. After free slots are exhausted, released candidates and same-control candidates precede global fallback. Finite keys may retain held flag8 after their cached EG goes inactive; the lease ensures that a control's prior PCM has ended before it is reused. A 2,000-allocation native snapshot test exercises this held-key reuse without replacing either Flame. Fully occupied synthetic pools explicitly demonstrate replacement/failure paths. There is no claim of special Flame protection at32 active slots.
10. **Maximum expected mix:** ten principal slots, no intentional audible voice stealing. Loop playback remains persistent: one Attack, program preselection, one Loop at38 VBlanks, finite Attack key retired next VBlank, no periodic Loop restart. Persistent Loop receives Note Off only from its existing release/pause/death/state cleanup. The finite Attack retirement is preserved and is not a Loop stop.
